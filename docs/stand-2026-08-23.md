## 2. Die drei Regeln, die alles andere erklären

**Speicherorte** (ausführlich in `docs/speicherorte.md`)

> Supabase ist das System of Record.
> Der Memory-Store ist der Arbeitsspeicher einer Sitzung.
> Die Files API ist eine Schleuse, kein Ablageort.

Kein Agent spricht direkt mit Supabase. Das Backend projiziert vor der Sitzung
hinein (`wissenProjizieren`) und holt danach zurück (`analysenUebernehmen`,
`wissenUebernehmen`, `lieferungenUebernehmen`) — alles in
`lib/agents/speicherProjektion.ts`.

Grund: Ein Agent, der selbst schreibt, braucht den Service-Role-Key, und der
umgeht Row Level Security vollständig. Bei einem System, dessen Eingabe
Werbetexte von fremden Websites sind, ist das eine offene Flanke.

Grenzen: Memory nimmt nur **Text bis 100 KB** je Eintrag. PDFs und Videos gehen
über Session-Outputs in den Storage-Bucket `lieferungen` (privat, 150 MB,
signierte Links mit einer Stunde Gültigkeit).

**Master und Kopie** (`lib/anthropic/kundenkopie.ts`)

Agenten sind workspace-gebunden. Der Katalog liegt im Workspace *KANA AI*, jeder
Kunde bekommt Kopien in seinem eigenen. Gekauft wird der Master, gestartet die
Kopie; `agent_access1` zeigt auf den Master.

In der Datenbank: `organization_id` und `master_agent_id` sind entweder **beide**
gesetzt (Kopie) oder **beide** leer (Master) — erzwungen durch
`agents_master_oder_kopie`. Eine Kopie kann nicht veröffentlicht werden
(`agents_kopie_nie_veroeffentlicht`).

**Mandantenneutralität** (`docs/neuer-mandant.md`)

Kein Prompt kennt eine Marke. Alles Mandantenspezifische steht in
`/mnt/memory/kana-wissen/marke.json`: Name, Kürzel, Domain, Kanäle,
Hauptprodukt, Tonalität, Ausschlussliste, Suchbegriffe, Wettbewerber, Quellen.

Ein neuer Kunde ist im Kern eine ausgefüllte JSON-Datei plus
`scripts/mandant-einrichten.mjs`. Richtwert zwei bis drei Stunden.

**5. Outcomes.** Rubriken liegen unter `agents/rubriken/`, sind aber nicht
scharf geschaltet — sie vervielfachen die Kosten je Lauf (`max_iterations`).

## 6. Fallstricke, die an diesem Tag Zeit gekostet haben

**Branch-Aktualität zuerst prüfen.** `feat/onboarding` lag 14 Commits hinter
`main`, darunter der komplette Relaunch. Die halbe Tagesarbeit entstand auf
einem veralteten Stand, und das Preview-Deployment zeigte ein älteres Design als
Production. `git fetch && git log HEAD..origin/main --oneline` als Erstes.

**`list_tables` meldet `rows: 0` für nie analysierte Tabellen.** Das ist eine
Planner-Statistik, kein Zählwert. Führte zur falschen Aussage „keine
Datengrundlage", obwohl acht Ads und fünf Wissenseinträge dalagen. Immer
`select count(*)`.

**Roster-Pins hinken.** Ein Koordinator hält die Version seiner Unteragenten
fest, wie sie beim Speichern war — auch wenn man nur die blanke ID schickt.
Nach jeder Änderung an einem Unteragenten
`node scripts/roster-nachziehen.mjs --schreiben`. Das war der ursprüngliche Bug:
Der Roster stand auf `version: 1`, während der Dokumentenbauer bei v5 war.

**`PATCH` auf `/v1/memory_stores/…/memories/…` antwortet 405.** Die Doku nennt
PATCH, die API nimmt es nicht. Stattdessen `DELETE` und neu anlegen.

**Skills sind workspace-gebunden.** Eine `skill_id` aus dem Quellworkspace lässt
den Agent-Create im Ziel mit 400 auffliegen. `mandant-einrichten.mjs` bildet sie
über den Anzeigenamen ab.

**`allowed_hosts` erlaubt Wildcards.** `*.fbcdn.net` deckt Facebooks wechselnde
Video-Subdomains ab. Stand in einem alten Environment und war die Lösung für ein
Problem, das ich schon als ungelöst dokumentiert hatte.

**`files.list({scope_id})` braucht zwei Beta-Header.** Die SDK setzt nur
`files-api-2025-04-14`; ohne `managed-agents-2026-04-01` wird `scope_id`
abgewiesen. Dazu ein bis drei Sekunden Indexierungsverzögerung nach `idle`.

**Die CI-Schriften führen ☐ und ☑ im cmap, setzen sie aber leer.** Fällt erst im
fertigen PDF auf. Checklisten-Zeichen werden deshalb gezeichnet, nicht gesetzt.

**Kundenkopien heißen exakt wie ihr Master.** Der Name unterscheidet sie nicht
mehr — nur `master_agent_id`. Betrifft Sync, Admin-Ansicht und jede Abfrage, die
über den Namen geht.
